# راه‌اندازی اولیه GPT Yar

این مراحل فقط برای آماده‌سازی اولیه زیرساخت است. برای خرید، تمدید، تغییر قیمت، ثبت توکن ربات/کیف پول، آموزش و نسخهٔ افزونه به مراجعهٔ روزانه به Supabase یا اجرای دستور نیاز نیست.

## اتصال ضروری

با دستور صریح مدیر، همین پروژهٔ متصل `isfahan-education-system` با ref برابر `efibfevyiepkwpnobaro` برای GPT Yar استفاده شد. ۲۵ جدول و توابع برنامه با پیشوند `gptyar_`، سه bucket خصوصی و Edge Function به نام `gptyar-api` ایجاد شده‌اند. نام و سامانهٔ آموزشی قبلی تغییر نکرده‌اند. نشانی واقعی Backend: `https://efibfevyiepkwpnobaro.supabase.co/functions/v1/gptyar-api`. ساخت پروژهٔ تازه لازم نیست.

Migration با نسخهٔ واقعی `20261018161002` و نام `gptyar_commerce` ثبت شده است. برای وضعیت و باقی‌مانده‌های راه‌اندازی، [گزارش تحویل](DELIVERY-fa.md) را ببینید. Secrets اختصاصی و Cron هنوز تنظیم نشده‌اند.

توکن مدیریت، توکن ربات، provider_token و service_role را در پیام، Issue، کد عمومی یا `config.js` قرار ندهید. توکن‌های ربات و پرداخت فقط بعد از استقرار در پنل وارد می‌شوند.

## آماده‌سازی فنی یک‌بار

روی دستگاه امن مسئول راه‌اندازی، Node 24، Deno 2.9.6 و Supabase CLI را آماده کنید. این کد با CLI 2.83.0 بررسی شده است؛ CLI جدیدتر را ابتدا با `--help` بررسی کنید. برای این پروژه Docker الزامی نیست و Edge Function می‌تواند با `--use-api` بسته‌بندی شود.

1. در مخزن `extensions` آزمون‌ها را اجرا کنید:

   ```sh
   npm ci --ignore-scripts
   npm test
   deno task check
   ```

2. Migration اولیه روی پروژهٔ بالا اعمال شده است؛ آن را دوباره اجرا نکنید. فرمان‌های زیر فقط برای نصب جدید و پس از تطبیق تاریخچهٔ کامل Migrationهای پروژه هستند:

   ```sh
   supabase login
   supabase link --project-ref YOUR_ACTUAL_PROJECT_REF
   supabase db push --dry-run
   supabase db push
   ```

   فایل Migration از نام‌های اختصاصی `gptyar_` استفاده می‌کند و حذف داده ندارد. در پروژهٔ مشترک، قبل از هر `db push` باید تاریخچهٔ Migrationهای سامانهٔ قبلی نیز در checkout زیرساخت موجود و هماهنگ باشد؛ `migration repair` یا حذف تاریخچه برای دور زدن اختلاف مجاز نیست. Migration اولیهٔ GPT Yar از طریق MCP اعمال و با PostgreSQL میزبانی‌شده بررسی شده است.

3. در **Edge Function Secrets** تنظیمات `.env.example` را ثبت کنید. مقادیر واقعی فقط در زیرساخت امن قرار گیرند:

   | متغیر | کاربرد |
   |---|---|
   | `GPTYAR_ENCRYPTION_KEY` | کلید تصادفی ۳۲ بایتی با encoding base64؛ نسخهٔ پشتیبان خارج از DB |
   | `GPTYAR_WORKER_SECRET` | مقدار تصادفی حداقل ۳۲ نویسه؛ فقط برای فراخوانی پردازشگر |
   | `GPTYAR_ACCOUNT_ID` | شناسه واقعی `account.id` از اعتبارسنجی مجاز GPT Yar، برای جلوگیری از ورود مدیر حساب دیگر |
   | `GPTYAR_EXTENSION_VERSION` | فعلاً `4.6.5` مطابق قرارداد ارسالی؛ تغییر فقط بعد از تأیید API |
   | `ADMIN_ORIGINS` | مبدا HTTPS پنل؛ پیش‌فرض `https://gptyar-web.github.io` |
   | `PUBLIC_ORIGINS` | مبدا HTTPS سایت عمومی؛ همان پیش‌فرض |
   | `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | در محیط استاندارد میزبانی‌شده Supabase در دسترس‌اند؛ Backend از service_role استفاده می‌کند |
   | `RELEASE_DOWNLOAD_HOSTS` | اختیاری؛ میزبان‌های مجاز فایل خارجی، جداشده با ویرگول؛ حالت پیش‌فرض دانلود Storage است |

   اگر `GPTYAR_ACCOUNT_ID` معلوم نیست، مسئول راه‌اندازی فقط با مجوز مدیر، `POST /accupdator/validate` و درخواست خواندن فهرست را بررسی و `account.id` را استخراج کند؛ نیازی به ساخت مشترک واقعی نیست. کلیدهای رمزنگاری/پردازشگر از generator امن سیستم ساخته شوند و در کد ثبت نشوند.

4. Edge Function اولیه مستقر شده است. برای انتشار نسخهٔ بعدی، با مجوز زیرساخت از فرمان زیر استفاده کنید:

   ```sh
   supabase functions deploy gptyar-api --project-ref YOUR_ACTUAL_PROJECT_REF --use-api
   ```

   `verify_jwt=false` در `supabase/config.toml` آگاهانه است: این سامانه توکن مدیریتی اختصاصی و Webhook دارد. همهٔ عملیات خصوصی در خود Backend احراز هویت می‌شوند. هیچ جدول مدیریتی به مرورگر باز نشده است.

5. زمان‌بندی پایدار را یک‌بار نصب کنید:

   ```sh
   python3 scripts/install-scheduler.py
   ```

   ابزار، project ref و access token زیرساخت و همان worker secret را به‌صورت تعاملی می‌گیرد. مقادیر محرمانه echo یا ذخیره نمی‌شوند. راز فراخوانی Cron در Supabase Vault قرار می‌گیرد. Worker هر دقیقه و پاک‌سازی روزانه اجرا می‌شوند. اولین پاسخ موفق Cron/Edge Function باید در زیرساخت بررسی شود. تا زمانی که پردازشگر اخیراً اجرا نشده باشد، فعال‌سازی ربات در پنل رد می‌شود.

6. نشانی **واقعی** Function را یک‌بار در فایل‌های عمومی سایت و پنل ثبت کنید:

   ```sh
   python3 scripts/configure-public.py \
     --api-base https://YOUR_ACTUAL_PROJECT_REF.supabase.co/functions/v1/gptyar-api \
     --website /path/to/gptyar-web.github.io
   ```

   این ابزار فقط نشانی عمومی را می‌نویسد. config پنل و وب‌سایت اکنون نشانی واقعی Function مستقرشده را دارند؛ انتشار فایل‌های عمومی همچنان از مسیر بررسی و ادغام مخازن انجام می‌شود.

7. دسترسی service_role به REST و توابع، RLS و Storage را در پروژه واقعی آزمایش و advisors را اجرا کنید. آزمون محلی، جایگزین بررسی محیط میزبانی‌شده نیست. GitHub Pages را از مسیر موجود پروژه منتشر کنید. Workflow تست، secret سرویس خارجی ندارد.

## راه‌اندازی داخل پنل

1. با توکن مدیریتی معتبر `@` وارد شوید؛ نام کاربری/ایمیل/رمز جداگانه وجود ندارد.
2. در «تنظیمات سامانه»، اجازه نگهداری رمزنگاری‌شده مجوز خودکار ربات را صریحاً تأیید کنید. بستن مرورگر این مجوز را حذف نمی‌کند. ابطال محلی و ابطال توکن نزد GPT Yar دو عملیات جدا هستند.
3. اگر محدودیت‌های کامل حساب از API برنمی‌گردد، حدود واقعیِ تأییدشده با ارائه‌دهنده را ثبت کنید. تا آن زمان فروش خودکار مسدود می‌ماند.
4. در «ربات بله» توکن **@gpryarbot** را ذخیره کنید. دریافت هویت، ثبت و بررسی Webhook انجام می‌شود. شناسهٔ ربات متفاوت پذیرفته نمی‌شود.
5. در «پرداخت بله» حالت آزمایشی را ثبت کنید؛ توکن تست رسمی در Backend استفاده می‌شود. یک گفت‌وگوی خصوصی با `/start` باز کنید، شناسهٔ عددی خود را برای صورتحساب اعتبارسنجی بدهید و آزمایش را انجام دهید.
6. پرداخت آزمایشی را فعال و جریان خرید، دریافت نام و نام خانوادگی و پیام پایان آزمون را بررسی کنید. سفارش تست **حساب واقعی صادر نمی‌کند**.
7. برای حالت واقعی، provider_token واقعی BotFather را با تأیید صریح ثبت کنید. با دکمه اعتبارسنجی، صورتحساب **واقعی ۱۰۰۰ ریالی** درخواست کنید؛ این صورت‌حساب اشتراک نمی‌سازد. فقط پس از رسید معتبر و استعلام `paid`، اتصال واقعی تأیید می‌شود. سپس پرداخت واقعی را فعال کنید.
8. برای آزمون صدور/تمدید زنده، فقط از حساب آزمایشی مورد تأیید ارائه‌دهنده و مجوز مدیر استفاده کنید. این آزمون در این نشست انجام نشده است.
9. برای اعلان خطای فروش، در تنظیمات روی اتصال گفت‌وگوی مدیر بزنید و خودتان پیوند یک‌بارمصرف بله را باز کنید. خطاهای صدور به همان گفت‌وگوی خصوصی اعلان می‌شوند.
10. قیمت، تخفیف، فیلم و نسخه را از پنل مدیریت کنید. فایل‌های آموزش باید توسط مدیر دارای مجوز بارگذاری شوند.

## اتصال اولیه کانال بروزرسانی افزونه

افزونه ۴.۶.۵ نصب‌شده خودبه‌خود به API جدید متصل نمی‌شود. در مخزن `chatgpt`، یک‌بار از Actions → Build managed extension package، نشانی عمومی واقعی Function را وارد و ZIP نسخه ۴.۶.۶ را دریافت کنید. یا مسئول راه‌اندازی `scripts/package.py` را اجرا کند. ZIP را در پنل بارگذاری و ابتدا اختیاری منتشر کنید. نصب در Chrome دستی است.

پیش از توزیع ۴.۶.۶، سازگاری شماره نسخه آن با API اصلی GPT Yar باید عملاً تأیید شود. این API بیرون از کنترل مخازن است. در صورت رد نسخه، هماهنگی با مالک سرور ضروری است؛ شماره نسخه در درخواست‌های احراز هویت نباید پنهانی جعل شود.

## خروج از سرویس و بازیابی

- غیرفعال‌سازی ربات، فروش و مکالمات جدید را متوقف می‌کند؛ رسید پرداخت‌های قبلی همچنان ثبت و بررسی می‌شود.
- غیرفعال‌سازی پرداخت، PreCheckout فروش‌های جدید را رد می‌کند؛ سفارش پرداخت‌شده حذف نمی‌شود.
- برای نتیجه نامشخص ساخت، دکمه «تطبیق و تلاش امن» فقط وضعیت موجود را بررسی می‌کند و ساخت کورکورانه انجام نمی‌دهد. در نبود نتیجه قطعی، بررسی با ارائه‌دهنده و بازپرداخت واقعی لازم است.
- بازپرداخت واقعی مطابق امکانات/پشتیبانی بله انجام و شناسه آن در پنل ثبت شود. متد API بازپرداخت ساختگی وجود ندارد.
- نسخه پشتیبان PostgreSQL و کلید رمزنگاری هر دو لازم‌اند. تغییر کلید اصلی بدون بازرمزنگاری، داده‌ها را غیرقابل خواندن می‌کند.

انتشار نسخه در کانال مدیریت‌شده فقط زمانی پذیرفته می‌شود که بسته، wrapper سازگار و نشانی همین Backend را داشته باشد. نسخه‌های اصلی فاقد این اتصال می‌توانند بایگانی شوند، اما انتشارشان به‌عنوان نسخهٔ متصل به سامانه مسدود است؛ این کنترل از قطع شدن مدیریت بروزرسانی بعد از نصب بسته نامرتبط جلوگیری می‌کند.
